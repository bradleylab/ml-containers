# Fully-resolved transitive closure for the pin set in aifs/Dockerfile.
#
# Why this file exists: pip's resolver could not converge on the top-level
# pins on its own. It walked mirlib, contourpy, cftime and then cfunits
# downwards one release at a time, and died 17 minutes in on the cfunits
# 3.3.2 sdist, whose setup.py no longer runs under current setuptools. The
# pin set is not in conflict — uv resolves it in seconds, and the resolution
# it produces agrees with the checkpoint repo's own uv.lock on every package
# in the anemoi / earthkit / ecCodes chain (cfunits 3.3.7, eccodeslib
# 2.46.2.19, mir-python 1.28.1.19). What pip needed was the answer, not a
# search.
#
# Passing this as `pip install -c constraints.txt` leaves exactly one
# candidate version per package, so pip cannot backtrack. A pin here that
# contradicts a package's own requirement fails the build loudly, which is
# the point.
#
# Regenerate (from the same top-level pins the Dockerfile installs, plus
# torch-geometric, which layer 1 installs and the resolve must not move):
#
#   uv pip compile --python-version 3.12 \
#     --python-platform x86_64-manylinux_2_28 \
#     --no-header --no-annotate --strip-extras \
#     -o aifs/constraints.txt <requirements-in>
#
# Extras must be stripped: pip rejects a constraints file that carries them.
#
# One entry does more than pin a runtime package: pip applies constraints to
# the isolated environments it builds sdists in, so the `setuptools` line below
# also fixes the build backend cfunits is built with. That is the version
# cfunits 3.3.7 was verified against, and it takes whatever setuptools PyPI
# happens to serve on the day out of the picture.
#
